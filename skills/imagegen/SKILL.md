# 图片生成与编辑

仅当用户期望获得实际图片，或者要求修改现有图片时，使用 `ly_image` 工具。

用户不需要了解、提及或指定 `ly_image`。工具选择属于 Agent 的内部执行逻辑。

## 核心判断原则

调用图片工具之前，先判断用户期望的最终交付物。

- 如果最终交付物是实际图片，执行图片生成或图片编辑。
- 如果最终交付物是文字提示词，只输出文字，不执行图片生成。
- “生成图片”属于图片生成请求。
- “生成图片提示词”属于文字生成请求。
- 即使提示词已经完整并且可以直接用于生图，也不能将其视为用户已经授权生成图片。
- 用户不需要说出具体工具名称，只需要明确表达自己想获得的结果。

## 应当调用图片工具的情况

当用户的自然语言明确表示最终需要一张实际图片时，应调用 `ly_image`。

例如：

- “帮我画一只坐在月球上的猫。”
- “生成一张电影感的城市夜景。”
- “给这个产品做一张宣传图。”
- “把这张照片改成动漫风格。”
- “删除图片中的路人。”
- “把人物衣服改成黑色。”
- “使用刚才的提示词出图。”
- “按照这个 Prompt 生成图片。”
- “开始渲染。”

以上请求的最终交付物都是实际图片。

## 不得调用图片工具的情况

当用户期望的最终交付物是文字提示词、提示词分析或创作方案时，不得调用 `ly_image`。

例如：

- “帮我写一个生图提示词。”
- “生成一段图片 Prompt。”
- “给我一份 Midjourney 提示词。”
- “优化一下这段图片提示词。”
- “把这个提示词翻译成英文。”
- “分析一下这个 Prompt。”
- “给我三个不同风格的生图提示词。”
- “按照这个模板输出提示词。”
- “把这张参考图转换成文字提示词。”

这些请求中的“生成”指生成文字，不是生成图片。

处理此类请求时：

- 只输出用户要求的提示词、分析或文字内容。
- 不得调用 `ly_image`。
- 不得调用其他图片生成或图片编辑工具。
- 不得在输出提示词后自动继续生成图片。
- 不得因为提示词已经足够完整而推断用户希望立即出图。
- 如果当前正在执行一个提示词生成 Skill，应让该 Skill 完成文字交付，不得自动衔接生图流程。

## 会话上下文判断

判断用户意图时，应结合当前请求和会话上下文。

例如：

- 用户先要求编写提示词，随后说“再给我一个暖色版本”，仍然属于提示词任务。
- 用户先获得提示词，随后说“就用第二个生成图片”，此时属于图片生成任务。
- 用户上传参考图并要求“分析它的画面风格”，属于文字分析任务。
- 用户上传参考图并要求“按照这个风格生成一张新图”，属于参考图生图任务。
- 用户上传图片并要求“把背景换成海边”，属于图片编辑任务。

不得因为对话中出现了图片、参考图或完整提示词，就自动认定用户要求生图。

## 意图不明确时

优先根据以下信息判断：

1. 用户当前请求中明确表达的最终交付物。
2. 用户明确调用或当前正在执行的其他 Skill。
3. 当前对话所处的任务阶段。
4. 最近一轮相关上下文。

如果仍然无法判断用户想要的是图片还是提示词，应先进行简短确认，不得默认调用图片生成工具。

例如：

> 你希望我只输出生图提示词，还是直接生成图片？

## 职责范围

- 本 Skill 负责识别图片生成或编辑意图、整理图片指令、判断参考图角色，以及执行图片生成或编辑流程。
- 应用程序代码负责已发布的模型能力表、结构化界面选项、Provider 网关、任务状态和本地持久化资源。
- 不要在前端代码中重复实现本 Skill 的工作流程。
- 提示词编写 Skill 负责交付文字提示词；本 Skill 不得自动接管提示词任务并继续出图。

## 参数优先级

每个字段应独立按照以下顺序确定：

1. 用户在结构化界面中的明确选择。
2. 用户自然语言中的明确要求。
3. 管理员设置的模型默认值。
4. Provider 默认值。

`Auto` 或未选择的界面选项不属于明确选择。

不得改写模型支持的、用户已经明确选择的参数。

图片比例、分辨率、数量、格式和模型专属选项，应作为结构化工具参数传递，不要隐藏在提示词中。

## 生成与编辑的区别

### 生成新图片

在没有指定编辑目标的情况下创建新的图片资源。

### 参考图生成

根据一张或多张参考图创建新的图片资源。

参考图可以具有以下角色：

- `character`：人物或主体身份参考。
- `style`：画面风格参考。
- `composition`：构图或布局参考。

如果用户已经明确选择了参考图角色，必须保留用户的选择。

如果用户没有指定参考图角色，应结合会话中的图片内容和任务目标，选择最近且最相关的图片资源。

### 编辑现有图片

编辑是对一张已有图片进行修改，必须包含且只能包含一个 `edit-target`。

其他参考图片必须标记为以下角色之一：

- `character`
- `style`
- `composition`

不得将多张图片同时设置为 `edit-target`。

## 非破坏式编辑

不得覆盖输入图片。

每次编辑都必须生成新的 `assetId`，并将原始编辑目标保留为新资源的 `parentAssetId`。

除非用户明确要求改变，否则应保留以下非目标内容：

- 人物或主体身份。
- 原有构图。
- 光线关系。
- 材质和纹理。
- 颜色关系。
- 背景和环境。
- 其他未被用户指定修改的内容。

只修改用户明确要求改变的部分。

## 工具结果处理

`ly_image` 工具会在任务完成后，将生成结果下载到桌面会话的本地目录，然后再返回结果。

回复用户时：

- 使用工具返回的本地文件路径展示图片。
- 确认展示的是已经下载完成的本地资源。
- 工具结果和后续普通对话只引用 `assetId`、本地路径和必要元数据，不得复制或回显图片 Base64 正文。
- 只有用户明确选择图片执行识图、参考图生图或改图时，才把对应本地资源作为本轮图片附件传入。
- 不得依赖 APIMart 临时 URL。
- 不得将 APIMart 临时 URL 当作最终保存结果提供给用户。
