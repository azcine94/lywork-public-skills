# 设计来源与取舍

本文记录方法参考，不将仓库 Star 数作为效果证据；未复制项目源码、图片或完整 Skill。仓库会变化，本文不承诺当前 Star 数或生成效果。

## 1. 看图分析
- 项目：https://github.com/wuyoscar/GPT-Image2-Skill
- 参考：https://github.com/wuyoscar/GPT-Image2-Skill/blob/main/skills/get-prompt-from-image/SKILL.md
- 采用：识别主体、材质、光照、媒介、空间层次，提炼 3—5 个关键视觉锚点；不要虚构无法观察的摄影参数。
- 改造：原视角不是必须保留的锚点。将主体与世界信息同相机参数分离，避免“锁定原构图”与“移动相机”冲突。

## 2. 机位分类
- 项目与说明：https://github.com/jtydhr88/ComfyUI-qwenmultiangle
- 采用：方位、俯仰、景别分开规划，用明确观察位置代替含糊的“换角度”。
- 改造：复杂场景必须指定环绕中心、朝向基准和观察目标。不能把人物背面与场景后方混为一谈。
- 不采用：默认依赖 ComfyUI、Three.js、特定 LoRA 或 `<sks>` 触发词。

## 3. 跨视角案例
- 项目：https://github.com/PicoTrex/Awesome-Nano-Banana-images
- 采用：从明确位置朝明确目标观看，以及跨视角、俯视、多视图案例的测试思路。
- 改造：白底正交六视图适合单体，不作为完整环境场景默认模式。采用单张宫格汇总多个机位，不把宫格误当成白底正交资产展示。

## 4. 轴线与构图资料
- https://www.cadrage.app/the-180-degree-rule-in-filmmaking/
- 采用：轴线服务于空间方向感，依当前关系识别；用于连续镜头组织，不当作固定角度配方。
- https://www.cadrage.app/shot-composition-framing/
- 采用：用纵深、视觉权重、视线空间与现有场景构图引导注意；不将构图手段与情绪一一机械对应。
- https://en.wikipedia.org/wiki/30-degree_rule
- 采用：相邻镜头需有可感知变化的剪辑参考；不写成每格必须转30度，不把角度数值当作叙事或效果证据。
这些资料支持电影语言概念，不证明生图模型能精确保持几何；创造力不等于越轴。

## 原创补充
空间为最高硬约束，再进行导演判断、轴线组织和创造性观察；已观察/估计/未知信息分离，备选机位与顺序阅读分离，按空间、表达、差异和连续性筛选，不设固定机位或创意配额。同一原图约束全格、完整宫格提示词自包含、模型格式条件启用和出图授权边界。
