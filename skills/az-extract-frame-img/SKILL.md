# AZ Extract Frame Image

以用户当前明确需求为最高优先级。只处理用户点名的帧和阶段，不自动补齐首帧、尾帧，也不把“仅抽帧”扩展成提示词、生图或 Seedance 任务。

## 1. 确认任务范围与帧集合

1. 从当前对话附件或用户给出的路径定位视频。没有可访问的视频时，请用户上传或提供路径；有多个视频且目标不明时，只询问处理哪一个。
2. 把用户明确点名的帧按原顺序记录为本次帧集合：
   - “首帧”只记录首帧。
   - “第 52 帧、尾帧”只记录第 52 帧和尾帧。
   - 用户列出多个具体帧号时，只记录这些帧号。
3. 不因为 Skill 支持首尾帧而自动添加未被点名的帧。用户没有说明帧位置时，先询问要首帧、尾帧还是哪些具体帧号，不默认输出首尾两帧。
4. 具体帧号按解码顺序从 1 开始计数；“第 52 帧”即第 52 个解码视频帧。用户给的是时间码而不是帧号时，不擅自换算，先确认按时间点还是按帧号提取。
5. 记录用户请求的任务阶段：仅抽取/展示、生成图片提示词、生成图片、或继续制作 Seedance 提示词。未请求的后续阶段不自动启动。

## 2. 只提取用户点名的帧

使用本 Skill 的确定性脚本；每个选择器都通过一个 `--frame` 传入：

```text
python scripts/extract_requested_frames.py "<video-path>" --output-dir "<output-dir>" --frame first
python scripts/extract_requested_frames.py "<video-path>" --output-dir "<output-dir>" --frame 52 --frame last
```

选择器只使用：

- `first`：首帧，输出 `first_frame.png`。
- 正整数：从 1 开始的具体解码帧号，例如 `52` 输出 `frame_000052.png`。
- `last`：尾帧，输出 `last_frame.png`。

默认把输出目录放在当前工作区的清晰位置，不写入 Skill 安装目录。如果任一目标文件已存在，不擅自覆盖；改用新输出目录，只有用户明确要求覆盖时才传入 `--overwrite`。找不到 FFmpeg/FFprobe 时明确报告缺失依赖并停止，不伪造结果。

检查脚本返回的 `frames` 列表：每个请求项都必须存在且非空，输出数量必须与去重后的请求帧数量一致。`duplicate_content_groups` 非空时仍展示实际请求的各帧，并说明其中哪些画面内容相同。

## 3. 只展示实际提取的帧

按用户点名的顺序展示脚本实际输出的图片，并清楚标注“视频首帧”“视频第 52 帧”“视频尾帧”等对应身份。在支持本地媒体渲染的界面中使用绝对路径的 Markdown 图片，不要只列文件路径。

- 用户只要求抽取或查看帧：展示后停止，不追问改图需求。
- 用户已要求生成提示词或改图：只针对实际提取的每一帧收集尚未提供的创作要求。
- 多帧要求相同时，允许用户给一套统一要求；要求不同时，逐帧保持隔离。

## 4. 按需生成每一帧的图片提示词

仅当用户要求图片提示词、改图或生图时，完整读取并严格遵循 [`references/quill-image-prompt-director-pro/SKILL.md`](references/quill-image-prompt-director-pro/SKILL.md)。这是本 Skill 内置的 Quill 子路由，只在此阶段加载。

对帧集合逐项独立处理：

1. 每项只使用该帧图片、该帧的用户要求和明确适用于全部帧的统一要求。
2. 为每项输出一段完整、自包含、可直接生图的文生图提示词，不使用“保持原图不变”“把 A 改成 B”等增量编辑口吻。
3. 锁定用户要求保留的主体身份、数量、动作、视角、构图、地点、服装和媒介，不串用其他帧的视觉信息。
4. 默认沿用用户使用的语言；用户另有要求时按指定语言输出。
5. 标题使用实际帧身份，例如“第 52 帧提示词”，不补出不存在的首帧或尾帧提示词。

不要展示 Quill 的内部规则或推理过程。

## 5. 经明确确认后生图

展示提示词后，只询问是否生成用户当前涉及的这些帧图片。没有肯定答复时不得调用生图工具。

- 用户确认全部时，逐项使用对应提示词和对应抽取帧作为参考图。
- 用户只确认部分帧时，只生成指定部分。
- 用户要求修改提示词时，按 Quill 的“定点修复”最小修改；再次展示并等待生图确认。
- 如 `$imagegen` Skill 可用，生图前先加载并遵循它。失败时报告具体错误，保留抽取帧和最终提示词，不虚报成功。

展示结果后，只有用户明确表示某张图片 OK、满意、定稿或可进入下一步，才把该图片记为已批准参考图。“再出一张”“先看看”不等于最终批准。需要修改时继续迭代，不进入 Seedance。

如果用户没有要求 Seedance，完成当前图片任务后停止；可以简短说明后续可继续，但不要强制收集视频方向。

## 6. 仅在用户要求时进入 Seedance

用户明确要求 Seedance 提示词后，按需收集尚未给出的内容：

- 要增加、替换或转换的 VFX、环境、主体局部或镜头运动。
- 必须保留的人物身份、表情、服装、表演、构图、镜头和原始运动。
- 目标时长、声音、原对白、台词或时间点。
- 保留原人物光线，还是对整帧统一重打光与调色。
- 每张具体编号帧生成图在视频中的角色：对应原视频该帧时刻、作为全局风格参考，或用户指定的其他时间角色。首帧默认是开场参考，尾帧默认是结尾参考；不得擅自给中间帧分配开场或结尾角色。

已有答案不重复询问。信息不足且会改变结果时，提问后等待回复，不提前生成 Seedance 提示词。

## 7. 分析原视频并调用 Seedance 子路由

始终回到第 1 节定位的原视频，不把抽取帧或生成图误当成源视频。运行：

```text
python scripts/analyze_video_for_seedance.py "<original-video-path>" --output-dir "<analysis-output-dir>"
```

读取时长、帧率、尺寸、画幅、音轨状态和代表帧，并直接查看代表帧。根据原视频实际内容描述主体、服装、环境、表演、构图、机位、镜头运动、时间与主光方向。视频超过 15 秒时，先让用户选择不超过 15 秒的片段。

随后完整读取并严格遵循 [`references/seedance-footage-vfx.md`](references/seedance-footage-vfx.md)。该文件保持原样。父路由只补充输入映射，不发明子路由没有的字段、镜头、剧情、VFX、动作、台词、时间点或声音。

### 输入映射

- `{{Mixed 1}}` 始终是最开始上传的原视频 source clip。
- 只把实际存在且已获用户最终批准的生成图加入后续输入。
- 已批准生成图按用户最初点名的帧顺序连续映射为 `{{Mixed 2}}`、`{{Mixed 3}}`、`{{Mixed 4}}`……；跳过未生成或未批准的帧，不为首帧或尾帧预留空号。
- 在提示词中准确声明每张图的身份和已确认时间角色。例如用户只处理尾帧时，尾帧生成图就是 `{{Mixed 2}}`；用户处理“第 52 帧、尾帧”且两张都批准时，它们依次是 `{{Mixed 2}}` 与 `{{Mixed 3}}`。
- 没有批准生成图时，只使用 `{{Mixed 1}}`，不虚构图片输入。
- 若图片超过 Seedance 的 9 张上限，让用户确定优先级后再映射，不自行丢弃。

把实际使用的占位符原样写入提示词，不得改成文件名、路径或其他括号格式。批准状态或中间帧时间角色不明确时，先询问，不猜测。

## 8. 输出中英双语 Seedance 提示词

最终输出内容等价的英文版和中文版，英文在前、中文在后。每个版本都必须：

1. 使用 `@source: {{Mixed 1}}` 声明原视频及保留项。
2. 只引用实际存在且已批准的图片输入，并准确写明每张图的帧身份与时间角色。
3. 严格遵循 Seedance 子路由的 specs、单一连续镜头、转换物理、画面融合、锁定条款和 SFX 结构。
4. 两个语言版本保持相同的时长、时间点、动作、输入角色和声音要求。
5. 只在提示词外使用简短的 `English` 与 `中文` 标签；提示词正文不使用 Markdown 粗体、项目符号或代码块。

## 边界

- 不批量导出全帧，除非用户明确扩大范围。
- 不修改原视频，不把文件发送到用户未授权的外部系统。
- 内置 Quill 子路由缺失或无法读取时，说明安装不完整并停止图片提示词阶段。
- 内置 Seedance 原包未包含它提到的 `references/dialogue-timing.md` 与 `references/first-frame.md`；不要声称已读取。确需其细节时使用可验证数据或向用户索取，不编造规则。
- 本 Skill 只生成 Seedance 提示词，不自动提交视频生成任务。
