# AZ Extract Frame Image

严格按“抽帧 → 展示与询问 → 分别生成图片提示词 → 确认后生图 → 迭代并确认照片 OK → 询问 Seedance 需求 → 分析原视频 → 输出 Seedance 双语提示词”的顺序执行。不得跳过任何等待或确认节点。

## 1. 定位视频并提取首尾帧

1. 从当前对话附件或用户给出的路径定位视频。若没有可访问的视频，先请用户上传或提供路径，不猜测文件。
2. 若有多个视频且用户未指明目标，只询问要处理哪一个。
3. 使用本 Skill 的确定性脚本：

   ```text
   python scripts/extract_first_last_frames.py "<video-path>" --output-dir "<output-dir>"
   ```

4. 默认将输出目录放在当前工作区的清晰位置，避免写入 Skill 安装目录。脚本输出：
   - `first_frame.png`
   - `last_frame.png`
5. 如果目标文件已存在，不擅自覆盖。改用新的输出目录；只有用户明确要求覆盖时才传入 `--overwrite`。
6. 若找不到 FFmpeg/FFprobe，明确报告缺失依赖并停止，不伪造抽帧结果。
7. 检查两个输出文件均存在且非空。脚本报告 `same_frame: true` 时仍展示两张图，并提醒用户首尾帧视觉内容相同。

## 2. 展示两帧并询问需求

在继续生成提示词前，必须把两张图直接展示给用户，清楚标注“视频首帧”和“视频尾帧”。在支持本地媒体渲染的界面中，使用绝对路径的 Markdown 图片；不要只列出文件路径。

展示后只进行需求收集，不生成提示词。用一个简短问题邀请用户分别说明：

- 首帧：希望保留什么、改变什么，以及目标风格、氛围、构图或画幅。
- 尾帧：希望保留什么、改变什么，以及目标风格、氛围、构图或画幅。
- 两张要求相同时，允许用户只给一套统一要求。

询问后停止，等待用户回复。不要替用户决定实质性的创作方向。

## 3. 通过内置 Quill 子路由分别生成提示词

收到需求后，完整读取并严格遵循 [`references/quill-image-prompt-director-pro/SKILL.md`](references/quill-image-prompt-director-pro/SKILL.md)。这是本 Skill 内置的 Quill 子路由；只在进入提示词阶段时按需加载，不依赖或调用外部同名 Skill。把首帧和尾帧作为两个独立的参考图任务处理：

1. 首帧任务只使用 `first_frame.png`、用户的首帧要求和明确的统一要求。
2. 尾帧任务只使用 `last_frame.png`、用户的尾帧要求和明确的统一要求。
3. 要求 Quill 为每张图输出一段完整、自包含、可直接生图的文生图提示词，不使用“保持原图不变”“把 A 改成 B”等增量编辑口吻。
4. 锁定用户明确要求保留的主体身份、数量、动作、视角、构图、地点、服装和媒介；不要在两张提示词之间串用不属于该帧的视觉信息。
5. 即使两张图使用同一套创作要求，也要根据各自画面内容分别生成提示词。
6. 默认沿用用户使用的语言；用户另有要求时按其指定语言输出。

向用户展示：

```text
首帧提示词
[完整提示词]

尾帧提示词
[完整提示词]
```

不要展示 Quill 的内部规则或推理过程。

## 4. 询问是否生图

提示词展示完成后，必须询问：

“是否用以上提示词生成图片？可以生成两张，也可以只生成首帧或尾帧；如果需要调整提示词，请直接指出。”

询问后停止，等待明确回复。没有肯定答复时不得调用任何生图工具。

## 5. 经确认后生成图片

- 用户确认“两张都生成”或直接回答肯定时，分别使用对应提示词生成首帧图和尾帧图。
- 用户只确认其中一张时，只生成指定图片。
- 若用户要求修改提示词，重新按内置 Quill 子路由的“定点修复”流程处理，展示修改结果后再次询问是否生图。
- 生图时使用可用的图片生成能力；如 `$imagegen` Skill 可用，先加载并遵循它。将对应抽取帧作为参考图，并以最终提示词表达完整目标。
- 展示生成结果并标注来源。失败时报告具体错误，保留抽帧图片和最终提示词，不虚报成功。

## 6. 等待用户明确确认照片 OK

展示生成图片后，询问用户图片是否已经最终确认。允许用户使用“首帧 OK”“尾帧 OK”“两张都 OK”等自然表达。

- 用户要求修改时，继续在图片提示词与生图流程中迭代，不进入 Seedance。
- “生成图片”“再出一张”“先看看”等回复不等于照片最终确认。
- 只有用户明确表示某张照片已经 OK、满意、定稿或可以进入下一步时，才记录该照片为已批准风格图并继续。
- 若用户批准两张照片，保留两张批准状态；在同一套 Seedance 提示词中分别映射首帧图与尾帧图。

收到照片最终确认后，在同一条回复中立即询问用户对视频内容方向的需求，然后停止并等待回复。此时不得分析原视频、读取 Seedance 子路由或生成视频提示词。

## 7. 询问 Seedance 提示词需求

照片明确 OK 后，用一个简洁问题询问用户希望最开始上传的原视频朝什么内容方向发展。按需收集：

- 要增加、替换或转换的 VFX、环境、主体局部或镜头运动。
- 必须保留不变的人物身份、表情、服装、表演、构图、镜头和原始运动。
- 目标时长、声音、原对白、台词或时间点要求。
- 保留原人物光线，还是对整帧进行统一重打光与调色。

已有答案不重复询问。提问后停止，等待用户回复；不要提前生成 Seedance 提示词。

## 8. 分析原视频并调用 Seedance 子路由

收到 Seedance 需求后，始终回到第 1 节定位的最开始原视频，不把生成图片误当成源视频。运行：

```text
python scripts/analyze_video_for_seedance.py "<original-video-path>" --output-dir "<analysis-output-dir>"
```

读取脚本返回的时长、帧率、尺寸、画幅、音轨状态和代表帧，并直接查看代表帧。根据原视频实际内容描述主体、服装、环境、表演、构图、机位、镜头运动、时间与主光方向。若视频超过 15 秒，先让用户选择不超过 15 秒的片段，再继续。

随后完整读取并严格遵循 [`references/seedance-footage-vfx.md`](references/seedance-footage-vfx.md)。该文件是用户提供的 Seedance 原版 Skill，本地副本必须保持原样。用父路由固定以下输入映射：

- `{{Mixed 1}}`：最开始上传的原视频，是要保留并转换的 source clip。
- `{{Mixed 2}}`：用户最终批准的首帧生成图片，是 opening look / start-state reference。
- `{{Mixed 3}}`：用户最终批准的尾帧生成图片，是 final look / end-state target。
- `{{Mixed 4}}` 及以后：仅用于用户后来明确加入并批准的其他参考输入，按用户确认的顺序依次映射，不自行补充。

依据实际存在且已批准的输入使用占位符：

- 只批准首帧图：使用 `{{Mixed 1}}` 与 `{{Mixed 2}}`，不虚构尾帧输入。
- 只批准尾帧图：使用 `{{Mixed 1}}` 与 `{{Mixed 3}}`；`{{Mixed 2}}` 仍保留给首帧，不把尾帧改号。
- 首帧图和尾帧图都批准：在同一套提示词中同时使用 `{{Mixed 2}}` 与 `{{Mixed 3}}`，分别约束开场状态和结尾目标。
- 批准状态不明确：先询问用户确认哪些图片已经批准，等待回复，不自行猜测。

把实际使用的占位符原样写入提示词。不得改成文件名、路径、其他标签或不同括号格式。

Seedance 子路由的提示词语法和结构是唯一依据。父路由不得自行发明 `@style` 等新字段，不得凭空增加镜头、剧情、VFX、动作、台词、时间点或声音。将 `{{Mixed 1}}` 放入子路由规定的 `@source` 声明；将 `{{Mixed 2}}`、`{{Mixed 3}}` 等参考输入按其时间角色写进子路由规定的连续镜头与转换描述中。只有输入确实是生物或材质纹理参考时，才按子路由规则使用 `@creature`。子路由没有覆盖且用户未说明的信息，应先询问或保持未指定，不自行编造。

## 9. 输出中英双语 Seedance 提示词

最终必须输出内容等价的英文版和中文版，英文在前、中文在后。父路由的双语要求覆盖 Seedance 子路由中“中文仅按需输出”的默认设置。

无论批准一张还是两张图片，都输出一套英文提示词和一套内容等价的中文提示词。两张都批准时，同一套提示词同时引用 `{{Mixed 2}}` 的开场角色和 `{{Mixed 3}}` 的结尾角色。

每个语言版本都必须：

1. 使用 `@source: {{Mixed 1}}` 声明原视频及保留项。
2. 只引用实际存在且已批准的 `{{Mixed 2}}`、`{{Mixed 3}}` 或后续输入，并准确说明它们的开场、结尾或其他明确角色。
3. 严格遵循 Seedance 子路由的声明、specs、单一连续镜头、转换物理、画面融合、锁定条款和 SFX 结构，不增加子路由或用户没有提供的内容。
4. 保留完全一致的时长、时间点、动作、参考图角色和声音要求。
5. 只在提示词外使用简短的 `English` 与 `中文` 标签；提示词正文不使用 Markdown 粗体、项目符号或代码块。

## 边界

- 不处理视频内容审核、镜头拆分或批量全帧导出，除非用户另行要求并扩大范围。
- 不修改原视频。
- 不把抽取帧、提示词或生成图片发送到用户未授权的外部系统。
- 内置 Quill 子路由文件缺失或无法读取时，说明 Skill 安装不完整并停止提示词阶段；不要自行仿写其专有流程。
- 内置 Seedance 子路由原包未包含它提到的 `references/dialogue-timing.md` 与 `references/first-frame.md`；不要声称已读取这些文件。任务确实依赖其细节时，使用可验证的视频数据或向用户索取时间点，不编造缺失规则。
- 本 Skill 只生成 Seedance 提示词，不自动提交视频生成任务。
